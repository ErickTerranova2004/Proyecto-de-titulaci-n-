# 30 casos de prueba con repositorios públicos reales

Verificados el 2026-10-26 con `gh api` y `gh run list` (solo lectura). Datos en [casos_prueba_30.json](casos_prueba_30.json);
descartes en [casos_descartados.md](casos_descartados.md); carga y verificación de permisos con
[`scripts/cargar_casos_prueba.py`](../scripts/cargar_casos_prueba.py).

- **Ejecuciones**: ejecuciones completadas del workflow desde el 2026-04-26 (`total_count` de la API). El porcentaje se calcula
  sobre la muestra de las 100 más recientes.
- **NA / asig.**: lo ve en *Nuevo análisis* (`GET /api/repositorios/`) / en el panel de repositorios asignados
  (`GET /api/repositorios/?todos=1`).
- **Resultado esperado**: fijado con el comportamiento **real** del código (ver la sección «Lo que valida el registro»). Los
  INVÁLIDOS deberían rechazarse según el texto del formulario, pero el código los acepta: cada uno es un hallazgo.

## Lo que valida el registro (Fase 0)

- `POST /api/repositorios/registrar/` solo comprueba que el repositorio exista en GitHub (`/repos/{repo}`), que el archivo del
  workflow exista para la API de Actions (`/actions/workflows/{archivo}`, buscado **por nombre de archivo**) y que la evidencia
  tenga al menos 30 caracteres. **No lee ni analiza el YAML**: la decisión de que despliega se confía a la evidencia.
- Respuestas: **201** `{repositorio, workflow_path, ejecuciones_recientes (≤ 20), asignado_a}`; **400** formato o evidencia
  corta (`evidencia: …`) o usuario no válido (`usuario_no_valido`); **404** `github_no_encontrado` («El repositorio no existe en
  GitHub o es privado…» / «El workflow … no existe en …»); **409** `ya_registrado` («Este workflow ya está registrado y
  validado.»); 502/503 si GitHub falla o se agota la cuota.
- «Ya registrado» = mismo repositorio (por `github_id` o nombre) **y misma ruta**, con el workflow validado **y** disponible en
  GitHub. **No se comprueba la pertenencia al dataset base**: un repositorio del dataset con otra ruta se acepta, y un workflow
  del dataset marcado como no disponible se re-valida y su evidencia se sobrescribe.
- `sincronizar` pide las **20** ejecuciones más recientes de cada workflow validado y guarda solo las de `status=completed`
  (incluidas las `skipped` y `cancelled`); no las etiqueta. El etiquetado (éxito/fallo) solo ocurre al verificar una predicción,
  y `skipped` queda como `excluida_otro_resultado` (ni éxito ni fallo).
- El texto del formulario («servidor, nube o contenedores; no pruebas, documentación ni GitHub Pages») **no se aplica en el
  código**: publicar una imagen, GitHub Pages, CI o PyPI se aceptan si la evidencia tiene 30 caracteres.
